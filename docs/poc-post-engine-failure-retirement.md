# Review draft for POC cleanup after a failed Podman workload

Ubuntu #656 handles a failed Root preparation before the worker receives Incus access. A failed Heavy workload that already ran in Podman follows the existing retention policy. An empty Incus project at the end can establish current absence. It cannot establish that a VM never existed.

The local draft adds a private, read-only observation to `RootFinalizer`. It joins the original failed GitHub terminal record to the verified nonzero process exit and authenticates the complete stdout and stderr captures. It reuses the existing drain, disabled-fence, certificate, and Root ownership checks. It reads the exact project, bridge, default profile, instance list, operation list, and pool volumes twice. It also checks the exact project and bridge configuration and `used_by` with the same predicate used before deletion. Known VM history, an unknown effect, any operation or instance, an ambiguous volume, or changed state holds the observation. The observation has no production caller and authorizes no cleanup.

The private archive helper in `startup_retirement` seals the original lease record, its bound terminal observation, and both byte-exact captures under the existing Root lock. It uses the original capture hashes, inodes and limits. The archive remains outside the worker trees in a Root-only directory, and the return value carries a path and manifest SHA only. The readback verifies the exact file set, ownership, sizes, hashes and current original lease snapshot. A retry adopts a previously sealed archive only after the same readback. An orphan stage without a sealed archive holds for reconciliation before more files are copied. There is no archive upload or production caller.

The Root bootstrap draft can opt in one exact Business `heavy` selector by assigning its archived `post_engine_failure_policy_sha256`. The derived archive row binds that selector and keeps the previously selected Business policy and its retention period. Execution and observation resolve the same digest through the existing registry, ledger and signed context fields. The default and operating selections preserve their existing digests. Cleanup authorization still uses the existing policy. The current read-only observation holds any recorded image copy until the C19 checks are integrated.

## Integration before enabling this path

1. Use the Root bootstrap producer to opt in the approved Heavy selector and seal its derived policy in a fresh bank. Keep the protected producer and selected bootstrap independent from job input. Existing leases and planned operating cases retain their original policies.
2. Use the private post-engine archive helper for the native terminal record, bound exit, and complete stdout and stderr. Bind the archive destination to the existing Root storage quota and define reconciliation for orphan staging directories. Bind the separate fresh inventory and archive SHA to the original snapshot before arming cleanup. Preserve a durable original snapshot binding for the independent post-cleanup readback, since the archive helper currently expects that exact live lease state.
3. Bind the immutable archive and a fresh observation in a distinct failed-workload cleanup proof. Before authorization, use the pinned Incus backend to confirm that the scoped project has zero instances, volumes, operations, consumers, or foreign resources. Prove its image and bucket inventory using established `used_by` coverage or explicit enumeration. C19 Keycloak requires exactly one known private image copy with a verified `image-copy` effect, original fingerprint and owner. Reuse the C19 image retirement checks for its exact removal and independent absence readback. Any ambiguous or additional resource stays held. Under the existing Root session, reuse `cleanup_storage._no_consumers` on pinned worker and context identities and mount rows. Reuse `network_fence._namespace_witness` and `_namespace_refs_drained` with the original namespace identity and cookie as in `network_fence.remove`. These checks cover references beyond the drained worker cgroup. Extend `RootFinalizer.finalize` to require this proof for the opt-in failure and reuse its existing removal and postcheck sequence. Keep the failure archive separate from the sanitized business upload and exclude the failure path from `final_receipt_payload`. The current regular finalizer requires a public evidence spool and retained failure custody identifies a stopped VM, so changing the retention time alone cannot enable this case.
4. Have a separate Root observation confirm the retained archive, exact closed journal, absent project, bridge, certificates and volumes, and the release of the original worker resources. Reconcile only demonstrably verified receipts after interruption. An unknown mutation stays held. The original GitHub job remains failed and has no business acceptance or PASS receipt. Use the existing after-retention route when the original policy or this proof requires it.
